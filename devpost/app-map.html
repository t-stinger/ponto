v2: flexible fields, voice/text and three output formats

On conditions, 列名をそろえる maps each source header explicitly; 集計項目を選ぶ edits up to three grouping columns and eight sum/count/average/min/max metrics, their labels and order. flexible.ts validates the shared definition and calculates locally. Groups/IDs and counts retain their formatting; totals use accepted raw values.

話す・書く provides editable instructions and optional browser SpeechRecognition with separate audio-transmission confirmation. Recognition is not verified on an actual microphone. AI proposals require metadata/text transmission consent, column/operation review and explicit application. No live provider calls have been made.

Confirm the final result, select Excel/CSV/PDF, then download. outputs.ts generates formula-safe BOM CSV or landscape Japanese PDF from the same rows. Noto font source and license are bundled. XLSX is reread in the Worker. Existing saved recipes remain supported; input aliases are volatile, not persisted.

Integration verification is pending. Earlier test results below are historical v1 results, not extension completion evidence.

1. Choose source files

main.ts handles file selection/drop and selected worksheets. A Worker parses each input. Invalid input retains a visible error and cannot be used.

2. Calculate deterministic totals

worker.ts calls aggregate.ts. Decimal arithmetic calculates store totals and the overall total from accepted original values. Excluded amounts are validated too. Per-store rounding can differ from overall rounding.

3. Export and reread

tables.ts creates Result and Summary worksheets. The Worker rereads both before returning download bytes. Input/condition edits invalidate old output; user confirmation is still required.

4. Save and repair the next run

jobs.ts saves recipes in IndexedDB. Each version update is transactional; another tab's update blocks a stale overwrite. Required renamed columns stop the next run until corrected. Matching names do not prove unchanged business meaning.

5. AI boundary

contract.ts validates metadata/instructions and a narrow proposal. The local server handler sends metadata/instructions to an explicitly configured Codex model with no tools. The browser requires consent and proposal review; no actual API success/cost claim is made.
